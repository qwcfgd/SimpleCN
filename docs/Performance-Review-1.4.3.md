# SimpleCN V1.4.3 代码与性能检查

日期：2026-09-21。检查接收线程、报文缓存/表格/导出、图像采样与刷新，以及 View / ViewModel / Model 的调用边界。性能测量使用合成报文，不连接硬件。

## MVVM

现有 Qt Widgets MVVM 分层继续成立，`python scripts/check_mvvm_boundaries.py` 通过。界面负责控件、显示窗口与选择状态；ViewModel 组织通道和信号命令；模型/服务负责缓存、解码与导出；ChannelModel 通过线程消息桥接 ChannelWorker，SDK 操作留在 worker。此次改动没有引入底层对 View/ViewModel 的反向依赖，也没有让 ViewModel 创建控件或让 View 直接操作硬件。

FrameTableModel 是既有 Qt 展示模型：提供索引、角色和格式化数据，并持有会话记录；本次优化沿用这一边界。

## 已优化的重复工作

- 时间正则表达式改为复用，秒字符串在记录入库时生成，绘制直接读取已有字符串。
- 历史浏览不再构造仅供按 ID 合并使用的索引；相同位置且窗口长度不变时不重建。后台缓存增长后仍能在同一位置加载新长度。
- 展开信号的父行查找从逐行扫描改为有界哈希索引，重建/清空时同步失效。
- 同一报文键、相同负载和相同有效性标志复用解码结果；负载、错误/无响应/RTR 状态或数据库变化时仍重新解码。半字节着色直接比较位掩码，保持逐帧计数。
- 隐藏的历史滚动条不再跟随实时接收重复计算范围和提示；没有展开项时跳过全表展开状态扫描。
- 图像页收到无关报文或已去重的回读时，不再推进绘图刷新版本；有效采样、错误帧和状态变化仍触发刷新。
- CSV 不再复制完整缓存或构建未使用的通道映射；ASC/BLF 对有序缓存直接读取，只有乱序输入才复制并稳定排序，同一时刻的原始顺序保留。
- 删除采集线程中已被全局采集时钟替代的无效时钟成员及参数。

## 软件基准

同一台机器、Qt 6.8.4 Release、同一合成数据集，每项运行三次取中位数。优化前为 `17450f7` 的生产代码加同一个测量程序；优化后使用本次实现。各场景输出校验值一致。以下为耗时，单位毫秒：

| 工作量 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 暂停期间记录 100,000 条，每批 100 条 | 2692.260 | 119.137 |
| 实时追加 100,000 条，每批 100 条 | 2681.099 | 140.065 |
| 按 ID 更新/解码 100,000 条相同负载 | 4999.226 | 234.737 |
| 切换 200 次历史窗口，每窗口 10,000 条 | 2466.374 | 203.890 |
| 重复定位当前窗口 200 次 | 2456.472 | <0.001 |
| 读取时刻显示值 1,000,000 次 | 352.680 | 26.975 |
| 10,000 行下查询末行子项父索引 100,000 次 | 605.753 | 0.315 |

Windows 进程 CPU 时间的中位数：实时追加 2671.875 → 140.625 ms；按 ID 更新 5000 → 234.375 ms；暂停记录 2687.5 → 125 ms。CPU 时间具有系统计时粒度，极短场景可能报告 0，因此这些场景以上表耗时为准。这些数字衡量指定模型路径，不代表整个程序、硬件总线或所有负载的 CPU 占用比例；变化负载仍需正常解码。

复现命令：

```powershell
cmake --build --preset qt6 --target trace_performance_probe
& C:/Documents/0_Qt/build/qttemp/Qt-GeneralController-qt6/tests/trace_performance_probe.exe
```

基准目标默认不构建、不加入 CTest，也不进入程序发布目录。原始结果为同一 qttemp 构建目录下的 `performance-before.json` / `performance-after.json`。

## 回归验证

- Qt 5.15.19 / Qt 6.8.4 Release 构建通过，固定运行目录内的程序已更新。
- Qt 5：16/16 CTest 通过，118.43 秒；Qt 6：16/16 CTest 通过，174.34 秒。
- 新增检查覆盖重复负载的错误/无响应/RTR/长度变化、数据库重载、超出显示容量后的父索引、清空、同位置窗口增长、无关报文与回读去重后的绘图刷新，以及导出乱序和相同时间戳的稳定顺序。
- 原有完整缓存导出、暂停后台记录、中英文切换、协议、回放、图像与运行目录检查均随全量回归通过。MVVM 静态检查和 `git diff --check` 通过。
- 按此前要求未进行实机测试，性能结论仅来自软件基准。

## 保持的行为与边界

完整会话缓存、10,000 条显示上限、暂停期间继续记录、秒单位与精度、中英文切换、CSV 原始记录顺序和 ASC/BLF 稳定时间顺序均保持。协议计时、接收轮询、硬件调度和模拟快速回放频率没有改变。

检查中未发现新增的无界忙等待。模拟快速回放的 0 ms 调度用于既有快速回放行为；硬件发送/调度的短周期用于时序和状态确认。完整缓存仍随记录量增长，清空/退出后释放；导出仍同步构造文件内容，大规模导出的格式化、压缩及内存开销依然存在。本次没有改动导出交互或缓存生命周期。
