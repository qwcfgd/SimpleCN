# CDD 自动配置与 UDS 诊断

## 功能与数据来源

CAN01、LIN01 等通道页签位于窗口最左侧，竖向排列、横向显示文字。每个通道有“下载”和“UDS 诊断”两个子页。现有下载镜像、下载任务位于“下载”页；连接配置、报文监视、运行日志共用。

硬件选择区保持固定布局。下载镜像与下载任务左右排列，镜像区的 Driver、Application 各占一行；可拖动分隔条调整下载镜像 / 任务的宽度、任务页 / 监视区的高度、报文监视 / 日志和 UDS 服务表 / 编辑区的宽度，以及请求参数 / 报文（RAW）/ 解析结果的高度。仅 UDS 页为监视区保留主窗口客户区高度的至少 30%。下载页与 UDS 页各自保留高度比例，切换页面时恢复；比例在当前窗口内保持，不写入通道配置文件。

运行时解析用户选择的 CDD，按所选 ECU / Variant 生成服务表和参数表。生产代码不包含测试文件路径、目标 ECU 名称、固定 DID 清单或测试服务数量。`testsrc/` 中的文件仅用于本地验收，程序运行不依赖该目录。

重新载入文件（包括同一路径下替换内容）会更新服务、参数类型、长度、枚举和指令，并清除原服务的输入及自定义 RAW 状态。解析失败时保留上一次有效配置并显示错误。各通道独立保存 CDD 路径及目标 ID，随通道配置保存、恢复；路径在条件允许时相对于配置文件保存。导入和切换目标不会自动发送请求。

## 操作步骤

1. 进入“UDS 诊断”，点击诊断控制台右上角的“UDS 设置…”。弹窗大小、滚动与保存/取消方式和下载设置一致。
2. 点击“选择 CDD…”后自动读取；也可输入路径后回车。ECU / Variant 选定或输入已有名称、QUAL、ID 后自动切换，并更新通信参数。所有修改先在弹窗中预览，“保存”后整体生效；“取消”保留之前配置。无需另点载入或应用目标按钮。
3. 用名称、SID、DID、RID 搜索服务，填写右侧请求参数，报文（RAW）实时显示最终指令，也可直接编辑 RAW。“发送”旁的“撤销”恢复自定义修改前由参数生成的报文。
4. 连接通道，点击“发送”。按钮变为“取消发送”，可停止正在发送、等待响应或等待超时的请求，也可停止重发间隔。解析结果区显示请求、响应 HEX、字段解析及 NRC。
5. 请求进行中，“UDS 设置”禁用并变灰，参数编辑锁定。发送使用点击瞬间冻结的服务、参数/RAW 报文与协议配置，自动重发也沿用该快照。断连、失败或取消会停止后续发送，下载与诊断互斥。

## 自动重发

在“UDS 设置”中勾选“自动重发”，设置额外发送次数及完成后延时（ms），保存后点击主面板“发送”启动。次数 2 表示首次发送加 2 次重发，共 3 次。前一次完成后才开始计时；失败立即停止。“取消发送”在等待间隔内也有效。设置随通道配置保存，启动程序不会自动发送。

## CDD 通信参数

解析属性定义的默认值，再按 ECU、基础 Variant、当前 Variant 的覆盖关系合并。会话层和网络层的数值参数以两列文本框展示：左侧是只读的程序默认值，右侧是实际使用值。CDD 只更新右侧，左侧保持不变。自动导入后可手动修改；重启时保留手动值，明确重新读取 CDD 或切换目标时再次应用 CDD 值。

- 会话层：P2 / P2* Client、P2 / P2* Server、P3 Client Phys、S3 Client、物理 TesterPresent 报文、RC78 等待总时限。P3 用于抑制正响应的等待；会话响应更新 P2/P2* 时保留 Client 与 Server 的非负余量。会话保持由勾选框启用，进入诊断会话后按周期发送 `3E 00` 或 `3E 80`；会话保持报文等待期间也禁用设置。
- CAN 网络层：请求、响应和功能 CAN ID、11/29 位 ID、BlockSize、STmin、N_As/N_Ar/N_Bs/N_Cr、填充字节和最大 PDU 长度。STmin 使用 ISO-TP 编码值；发送连续帧遵循对端 FlowControl。N_Ar 单独用于本机 FlowControl 发送确认。
- LIN 网络层：识别 `LIN.*` 命名空间的 P2/P2*、S3、TesterPresent、NAD、TimeoutAs、TimeoutCr、SlotTime。真实 LIN 调度仍遵循波特率决定的最短发送间隔。CAN 属性不会套用于 LIN。

CDD 没有相应属性时保留当前值。无法识别或尚未映射的 CAN/LIN 属性（例如 S3Server、TimeBr、TimeCs）在原始属性表中供核对，不会冒充已执行参数；这些服务端时序/性能预算不会被当成帧发送延时。CAN FD、扩展地址寻址和 DoIP 等命名空间不混入经典 CAN 配置。无效的已识别参数导入会提示原因，不替换当前配置。

下载页“参数配置…”与“UDS 设置…”共用会话层、网络层参数和默认值；保存合格 CDD 后两页同步更新。原通道设置中的 ID、NAD、29 位 ID、P2 等已移至下载参数配置。关闭“启用会话保持”时，周期与 TesterPresent 请求文本框禁用并变灰。

CDD 读取区域仅用指示灯显示协议匹配状态：未读取时灰色，匹配当前 CAN/LIN 通道时绿色，不匹配（或无法识别协议）时红色。明确不匹配的 CDD 不会覆盖当前参数。

CAN/LIN 波特率始终采用当前设备通道设置，不再在诊断设置中提供编辑控件，也不从 CDD 导入。空闲且已连接时可更新诊断协议参数；修改硬件波特率需先断开。功能 CAN ID 可编辑和保存，但当前请求执行范围仍为物理寻址。修改设置会重建诊断会话，之前的会话状态不沿用。

## 0x2E 等有输入参数的服务

`WriteDataByIdentifier (0x2E)` 的布局为 `2E + 两字节 DID + 数据`，DID 不是子功能。参数控件由该 DID 的 CDD 定义生成：

| CDD 字段 | 输入方式 | 编码与校验 |
| --- | --- | --- |
| 无符号 / 有符号整数 | 数值输入；十进制按物理值，`0x` 前缀按原始值 | 位宽、大小端、范围、排除值；线性比例和偏移 |
| 枚举或枚举区间 | 下拉选择，也可填写原始值 | 选项来自 CDD，检查合法值域 |
| ASCII / UTF 字符数组 | 文本输入 | 按编码后的长度校验；UTF-16 按 CDD 字节序编码 |
| 原始字节数组 | HEX 输入，例如 `01 02 A0` | 完整字节、长度范围及可选长度前缀 |
| 结构体 | 按定义顺序展开为多个字段 | 位域、固定值和数组组合编码 |

必填字段初始为空，禁止缺少参数时发送。整数值不会截断，字符串不会静默补零或裁剪。RAW 区域空闲时允许直接编辑完整请求，但仍检查所选服务的 SID、固定标识符、长度和字段约束。

例如合成测试文件定义 DID `F1A0` 为 16 bit 小端数值，输入 `4660` 生成 `2E F1 A0 34 12`；换成定义四字节标签的另一份 CDD 后，DID `1234` 输入 `ABCD` 生成 `2E 12 34 41 42 43 44`。这些规则都来自各自 CDD。

该机制同样用于 0x27 密钥、0x31 例程选项、0x34 地址 / 长度、0x36 数据块等参数。CDD 不提供的私有 seed/key 算法不能从描述文件推导；手动诊断需先执行所需会话、安全访问等服务，并填写相应数据。面板已移除执行条件及 CDD 版本/项目数提示；不会自动切换会话、解锁或串联业务流程。

## 解析与兼容范围

模型层由独立 `cdd_model` 库负责，使用 Qt XML 解析，无 Python 运行依赖。目前最高已验证版本为 CANdela 16.x。更高版本按现有最高版本规则尝试读取：成功时提示版本兼容性警告；XML、引用、服务或字段结构无法正确解析时拒绝导入，保留原数据库。版本号通过不等于该版本全部厂商扩展均已覆盖。

已实现的结构包括：

- ECU / VAR、DIAGCLASS / DIAGGROUP / DIAGINST / SERVICE；显式基础 Variant 引用的递归继承、覆盖及禁用；循环和缺失基础引用报错。
- PROTOCOLSERVICE、DCLSRVTMPL 引用链；类模板、服务模板、实例和服务级 STATICVALUE / SIMPLECOMPCONT 映射。
- SHSTATIC / STATICCOMPREF、SHPROXY / PROXYCOMPREF、DIDDATAREF / DIDREF、STRUCTURE / STRUCTDT。
- CONSTCOMP、STATICCOMP、DATAOBJ、GAPDATAOBJ、CONTENTCOMP、SIMPLEPROXYCOMP；内联 GODTCDATAOBJ / RECORDDATAOBJ。
- IDENT、TEXTTBL、LINCOMP、CVALUETYPE，定长 / 变长数组、长度前缀、枚举、位域、大小端、整数、BCD、浮点和字符数据。

无类型定义的代理数据区和 EOSITERCOMP 重复记录以原始 HEX 表示。NUMITERCOMP 支持前置计数字段引用及固定字节长度的记录，每条记录以 HEX 表示，严格校验计数与数据长度；无法界定的重复项仍明确报错。MUXCOMP / MUXDT、UNION 等条件结构当前显示不支持原因；不完整的请求禁止发送，无法结构化解码的响应保留原始 HEX 并显示原因。多个无边界变长字段不能可靠拆分时，校验会拒绝。当前传输 PDU 上限为 4095 字节，CDD 文件上限 32 MiB，不加载外部 DTD 或自定义 XML 实体。

当前执行物理寻址诊断；CDD 中仅支持功能寻址的服务仍显示在表格中，但禁用发送。ISO-TP 功能寻址多 ECU 响应收集未包含在本次实现中。

## 开源调研与实现选择

- [cantools](https://github.com/cantools/cantools) 提供 CDD 的 DID 数据解析与编解码，采用 MIT 许可；其 [CDD 解析器](https://github.com/cantools/cantools/blob/master/src/cantools/database/diagnostics/formats/cdd.py) 以 DID 数据库为主，不能直接满足此 Qt 项目所需的完整服务模板、Variant 和交互配置。
- [cdd_utils](https://github.com/fshoocn/cdd_utils) 覆盖较多 CDD 结构，使用 Python / xsdata；调研时未在仓库根目录找到明确许可文件，因此没有引入或复制其实现。

本次采用自行实现的 Qt 解析、编码和 UI 绑定，避免新增 Python 运行环境和不明确的代码许可依赖。

## 验证和硬件状态

本地验收 CDD（CANdela 15.0.4）识别出 39 项服务，包含两项 0x2E 写入定义；VIN 和多字段指纹指令已与预期字节对比。通用合成样本位于 `tests/fixtures/`，覆盖跨文件更新、Variant、服务模板、数值边界、大小端、字符串、长度、缺失引用、非法文件、CAN / LIN 分帧模拟发送与读写回读、取消和断连、通信属性默认值及目标覆盖、设置弹窗保存/取消、冻结报文、重发、TesterPresent 和布局切换。

较早版本的自动测试使用 2、8、12、14 版本标记的合成结构；这不替代各历史版本真实文件的兼容验收。后续拿到新的 CDD 后，应重点检查导入结果中的结构警告和代表性服务指令。

Qt 5.15.19 / Qt 6.8.4 均可构建。运行自动测试：

```powershell
$env:HOST_LIN_HARDWARE_TEST = '0'
ctest --test-dir <构建目录> --output-on-failure
```

模拟 CAN / LIN 使用实际协议分帧及 UDS 会话路径，模拟响应按 CDD 生成，可验证 0x2E 写入后 0x22 读回；模拟值与 ECU 的业务行为无关。已有 P2 / P2*、NRC 0x78、回显、取消、TesterPresent 机制复用，保活失败会结束排队的手动请求，避免界面一直等待。

online CAN 手动诊断通过 PCAN-Basic Echo Frames 确认总线发送，online LIN 复用 PLIN 发送回读；驱动不支持 CAN Echo Frames 时会明确报错。依据 [PEAK Echo Frames 文档](https://www.peak-system.com/documentation/API/PCAN-Basic.Net/html/4a6f0c95-988e-4873-8966-5e482b889cd1.htm)，PCAN 写入成功与实际发送确认分开处理。真实硬件联调按本次要求暂缓，未将模拟通过视为实机通过。原有真实 CAN 下载适配范围未扩展。
