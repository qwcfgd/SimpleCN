# 定版前逻辑修复（2026-09-20）

审查修复阶段处理以下七项问题并保留此前功能开发，当时等待用户核查。后续经用户授权，这些修复随 1.3 提交定版；当前构建布局与验证结果见 [1.3 发布说明](Release-1.3.md)。

| 问题 | 修复与验证 |
| --- | --- |
| LIN 回放停止失败仍显示停止 | 检查硬件清理结果；失败进入 Faulted 并保留 cleanupPending，阻止新任务和数据编辑，允许再次停止。正常结束、手动停止、链路故障均使用同一清理路径；成功断开后清除待清理状态。模拟 SDK 分别注入三种停止失败并验证重试恢复。 |
| 请求和回显导出后重复回放 | ASC 把真实发送请求写为注释，BLF 写为应用文本；硬件回显/接收帧仍是正常总线记录。仅请求、请求加回显、正常接收和模拟记录均覆盖读回验证。CSV 保留监视记录。 |
| LIN ID 修改扩大数据长度时尾部不确定 | 保留原数据，新增长度补 00，超出目标长度则截断；验证 2 字节修改为诊断帧后得到 AA BB 00 00 00 00 00 00，并能保存/恢复。 |
| LIN 接收校验类型受最后发送影响 | 普通帧用自身 PID、数据和校验字节判断 Classic/Enhanced；无法匹配则标记错误。诊断帧固定 Classic。不再用读取时的发送协议状态决定接收属性。 |
| LIN delay 撤销失效 | 先建立快照，再通过索引取得可写调度表；验证连续编辑与撤销均恢复原值。 |
| 已打开图像窗口读取配置不生效 | ViewModel 发出完整配置恢复通知，绘图模型重建实例、分组、颜色和选择，View 恢复光标、展示模式、坐标模式及视口；恢复期间禁止旧状态回写。再次读取同一配置不叠加信号。 |
| 非映射回放源切调度后卡住 | 回放期间禁止调度切换；停止回放组与停止本通道 worker 分开判定，无本地任务时不发送无效 run=0 停止命令。硬件停止未确认时也禁止切表。 |

## 完整回归补充修复

真实硬件已枚举时，在线模式切换到模拟模式可能把旧后端的通道带入新后端，连接按钮持续不可用。根因是 `commandFinished` 先于新后端首轮枚举，使旧列表被重新选中。现切换时清除旧通道与缓存，worker 在完成通知前发布新列表；新增缺失真实设备转模拟，以及已枚举通道双向切换的回归用例。原通道配置 UI 用例仍验证连接、断开、保存和重新加载；同时保证断言失败时关闭模态窗口，避免失败被掩盖成超时。

## 导出策略

真实发送请求只证明驱动接受请求，不代表已上总线。缺少硬件回显时，请求仍可在 CSV 和 ASC/BLF 注释中查看，但不会作为可回放总线帧。模拟报文保留原有导出行为。

## 验证

新增 9 个边界测试场景，分别位于 tests/test_workbench.cpp 和 tests/test_tosun.cpp。测试使用模拟 SDK、模拟通道、临时日志和 UI；模式切换测试允许真实设备枚举，不连接或发送实机报文。

Qt 5.15.19 / Qt 6.8.4 均完成全量构建及 CTest 回归，各 13/13 通过。新增场景覆盖手动停止、有限次回放完成、链路故障三种清理失败，以及日志去重、补零、撤销、图像恢复、回放调度保护和后端切换。

使用已有 python-can / vblf 独立读回也通过：2694 条 CAN/CAN FD、306 条 LIN 记录的内容、通道和时间匹配；混合记录的扩展帧、RTR、LIN 无响应/错误及原始 BLF 样例解析通过。CAN FD 仅验证文件格式，真实硬件仍限经典 CAN / LIN。

构建与测试产物分别位于 `C:/Documents/0_Qt/build/Qt-GeneralController-qt5` 和 `C:/Documents/0_Qt/build/Qt-GeneralController-qt6`，程序为其中的 `QtBootloader.exe`（窗口名称为 Qt-GeneralController V1.2）。

MVVM 边界保持：硬件清理由 Infrastructure 执行，任务状态和配置恢复通知由 ViewModel 管理；绘图控件与视口恢复留在 View。
